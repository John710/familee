# Familee — семейное древо

*Читать на другом языке: [English](README.md)*

Приложение для семейного архива: люди, союзы, события, места, источники и фотографии. Древо
рисуется наглядно — карточками с фотографией и полным именем, а щелчок по карточке открывает её
для редактирования. Интерфейс многоязычный; каждая строка живёт в `messages/*.json`.

Всё работает на вашем сервере в одном Docker-контейнере и подключается к уже запущенным на нём
контейнерам Postgres и Redis — собственных контейнеров для них приложение не поднимает. Вы выбираете,
как к нему обращаться: по IP-адресу сервера и порту (по умолчанию) или за Traefik по HTTPS с вашим доменом.

## Что умеет

- **Люди и семьи.** Персоны с именами, полом, датами рождения и смерти, записанными так, как их пишут
  люди («около 1901 года», «1921-04-12»), заметками, дополнительными именами и другими событиями с местами.
  Союзы с партнёрами и детьми; защита от петли в родословной.
- **Древо.** Карточки с фотографией и годами, сверху вниз. Щелчок открывает панель с хронологией,
  заметками и альбомом. Режим фокуса показывает предков и потомков одного человека; «связь со мной»
  называет родство каждой карточки с выбранным собой человеком; поиск центрирует древо на совпадении.
  Возраст показывается живым (сегодняшний) и умершим (тот, до которого они дожили).
- **Фотографии.** Альбом на каждого человека, главная фотография, обрезка квадрата, который видно на
  карточке, фотографии событий и галерея всего дерева.
- **Библиотека.** Места (с иерархией «входит в»), источники и цитаты для людей и событий, заметки и
  истории, поиск по всему архиву.
- **Дни рождения.** Ближайшие две недели по всем деревьям: колокольчик в шапке, главная, страница дерева,
  страницы участников и «Люди».
- **GEDCOM.** Импорт файла любой версии (версия читается из его заголовка) с предпросмотром и
  подтверждением; экспорт дерева в GEDCOM 7.0.
- **Доступ.** Роли в каждом дереве (владелец, администратор, соавтор, читатель), приглашения, сброс
  пароля, который выдаёт администратор, журнал изменений для владельца и администраторов и список
  устройств, с которых выполнен вход.

## Что внутри

Next.js 16.4 (App Router, server actions) на React 19.3 и TypeScript 7. Данные хранятся в Postgres и
запрашиваются через Drizzle ORM поверх драйвера postgres.js. Вход выполняет better-auth: сессии
живут в Postgres и кешируются в Redis (ioredis). Стили — Tailwind CSS 4 вместе
с daisyUI 5 и компонентами shadcn/ui на основе radix-ui. Переводы — next-intl. Линтинг и форматирование
— Biome. Древо рисуется через @xyflow/react; раскладка — собственный код в `src/lib/tree-layout.ts`.
Превью фотографий делает sharp.

Каждая зависимость закреплена на точной версии (без `^`) в `package.json`, а `package-lock.json`
фиксирует всё дерево. Обновление должно быть осознанным действием, а не побочным эффектом пересборки
образа.

## Требования к серверу

- Docker с плагином compose.
- Postgres (с доступными расширениями contrib — `pgcrypto`, `pg_trgm`, `btree_gin`) и Redis уже
  запущены и доступны по имени контейнера из одной Docker-сети (`DATA_NETWORK`).
- По желанию Traefik, если нужен HTTPS на домене. Без него архив открывается по IP-адресу.

Приложение подключается к сети данных и обращается к сервисам по имени контейнера.

## Первый запуск

**1. База данных.** Подключитесь к общему Postgres под суперпользователем и создайте роль и базу:

```sql
create role familee with login password 'pick_a_password';
create database familee owner familee;
```

Затем подключитесь к базе `familee` (тоже под суперпользователем) и включите расширения — обычной
роли это не разрешено:

```sql
create extension if not exists pgcrypto;
create extension if not exists pg_trgm;
create extension if not exists btree_gin;
```

Отдельная база необязательна. Все объекты приложения живут в схеме `familee`, поэтому схему можно
создать и внутри существующей базы. Тогда роли нужно право `create` на эту базу, а `DATABASE_URL`
указывает на её имя.

**2. Конфигурация.** Скопируйте `.env.example` в `.env` (права `600`) и заполните. Укажите `DATABASE_URL`,
`REDIS_URL`, `DATA_NETWORK` и `BETTER_AUTH_SECRET` (`openssl rand -base64 48`).

**3. Как открывается архив.** В `.env` выберите один из двух режимов:

- **По IP-адресу (по умолчанию).** Приложение публикуется на порту `FAMILEE_PORT` (по умолчанию 3000)
  сервера, по обычному HTTP. Укажите `BETTER_AUTH_URL=http://<ip-сервера>:<FAMILEE_PORT>`. Больше ничего
  не нужно. Обычный HTTP подходит только для закрытой сети; для интернета поставьте перед приложением
  прокси с HTTPS.
- **За Traefik по HTTPS.** Укажите `FAMILEE_HOST` — ваш домен, `BETTER_AUTH_URL=https://<домен>` и
  подключите файл-оверрайд в `.env`:

  ```bash
  COMPOSE_FILE=docker-compose.yml:docker-compose.traefik.yml
  ```

  В `TRUSTED_PROXIES` укажите подсеть этой сети (например `192.168.90.0/24`), чтобы лимит входов видел
  собственный адрес клиента. В режиме адрес и порт оставьте пустым.
  Оверрайд подключает сеть прокси `TRAEFIK_NETWORK`, добавляет метки маршрута для домена и убирает
  опубликованный порт, поэтому приложение доступно только через Traefik. Точку входа и резолвер
  сертификатов задают `TRAEFIK_ENTRYPOINT` и `TRAEFIK_CERTRESOLVER`.

`BETTER_AUTH_URL` должен совпадать с адресом, который видит браузер, включая схему и порт. Иначе вход
будет отклонён как пришедший с другого адреса.

**4. Сборка, схема, запуск.**

```bash
docker compose build
docker compose --profile tools run --rm migrate    # применяет db/migrations/*.sql
docker compose up -d
docker compose logs -f app
```

Сервис `migrate` — одноразовый контейнер, в котором есть только `psql`, поэтому клиент на сервер
устанавливать не нужно. Миграции идемпотентны: повторный запуск безопасен и предполагается после
каждого обновления кода.

**5. Демо-данные (необязательно).** `db/seed.sql` создаёт вымышленную семью на четыре поколения,
включая второй брак, пасынка и приблизительные или неполные даты. Это удобный способ увидеть дерево
до того, как вы внесли собственные данные.

```bash
docker compose --profile tools run --rm migrate seed
```

Скрипт полностью удаляет дерево со slug `demo` и пересоздаёт его при каждом запуске. Настоящие
деревья он не трогает.

## Учётные записи и доступ

Публичная регистрация закрыта. Первый человек один раз открывает `<BETTER_AUTH_URL>/setup` и
создаёт администратора; после этого страница отвечает 404. Остальные получают ссылку-приглашение от
владельца или администратора дерева. Ссылка действует 7 дней и работает один раз; токен показывается
только при создании и хранится как хэш.

Роли выдаются в пределах дерева: владелец, администратор, соавтор (роль `editor`), читатель. Приглашением
можно выдать любую роль, кроме владельца. Владелец или администратор меняет роль участника или отзывает доступ
на странице участников; администратор не трогает другого администратора и владельца, а свой доступ там не
меняет никто. В профиле каждый видит устройства, где вошёл, и может завершить любое из них.

`BETTER_AUTH_URL` должен совпадать с адресом, который видит браузер, включая порт (например
`http://192.168.0.10:3000` или `https://archive.example.com`). Иначе better-auth отклонит запросы как
пришедшие с другого адреса.

## Часовой пояс

`APP_TIME_ZONE` задаётся именем из базы IANA; по умолчанию это `Asia/Vladivostok`. Значение попадает в
переменную `TZ` контейнера, и Node.js использует её для всех отображаемых времён. Дни рождения
на ближайшие две недели (колокольчик, главная, страницы дерева, участников и «Люди») считаются от дня
в этом часовом поясе.

## Миграции и тесты базы

**Источник истины — рукописный SQL в `db/migrations/`.** Там гораздо больше, чем таблицы: триггеры,
функции обхода дерева (`familee.ancestors`, `familee.descendants`, `familee.kinship`), представления
`familee.parent_child` и `familee.person_cards`, проверки нечётких дат и защита от циклов в родстве.
Drizzle используется только как типизированный построитель запросов и вручную повторяет этот SQL
файл за файлом.

Поэтому **`drizzle-kit generate` запускать нельзя**: он не видит написанные вручную функции и
триггеры и сгенерировал бы миграцию, которая их удаляет. Подключены только безопасные команды:

```bash
npm run db:check     # сверить схему Drizzle с базой
npm run db:pull      # посмотреть, что реально лежит в базе
npm run db:studio    # просмотреть данные
```

Изменение схемы делается в два шага: сначала новый файл `db/migrations/000N_*.sql` (идемпотентный, со
своей транзакцией и строкой в `familee.schema_migrations`), затем соответствующий модуль в
`src/db/schema/`. Имена ограничений и индексов в SQL и в Drizzle должны совпадать — на этом держится
`db:check`.

Тесты базы лежат в `db/tests/smoke.sql`. Они проверяют демо-дерево, обход предков, функцию родства и
защиту от циклов. Каждая проверка выполняется внутри транзакции, которая откатывается, поэтому данные
остаются прежними:

```bash
docker compose --profile tools run --rm migrate seed test
```

## Языки

Добавление языка занимает ровно два шага: положить файл `messages/<код>.json` (проще всего начать с
копии `messages/en.json`) и добавить код в массив `locales` в `src/i18n/routing.ts`.

Файл не обязан быть переведён целиком. Любой отсутствующий или пустой ключ берётся из языка по
умолчанию, поэтому наполовину переведённый файл не ломает интерфейс — об этом заботится `withFallback`
в `src/i18n/request.ts`. `npm run test:i18n` проверяет, что у каталогов одинаковый набор ключей.

В базе данных нет ни одной человекочитаемой подписи. Значения перечислений, типы событий и степени
родства хранятся как ключи (`male`, `birth`, `marriage`), а их подписи лежат в `enums.*` и `events.*`
в файлах переводов. `familee.kinship()` возвращает два числа — сколько поколений вверх и сколько вниз,
а фразу вроде «троюродный брат» приложение составляет из `kinship.*`. Поэтому новый язык не требует
вообще никаких миграций.

Сам проект — комментарии, идентификаторы, документация — написан по-английски. Единственные русские
файлы — `messages/ru.json` и [README.ru.md](README.ru.md).

## Оформление

Палитра объявлена один раз — как две темы daisyUI (`light` и `dark`) в `src/app/globals.css`. Имена,
которые ожидают компоненты shadcn/ui (`bg-background`, `text-muted-foreground`, `border-border`),
объявлены в том же файле внутри `@theme inline` и **ссылаются** на цвета daisyUI. Так обе библиотеки
согласованы, а править палитру можно в одном месте.

Две детали легко «починить» по ошибке. Во-первых, имена, общие для обеих библиотек (`primary`,
`secondary`, `accent`, `info`, `success`, `warning`, `error`), никогда не переопределяются внутри
`@theme inline` — это создаёт циклическую ссылку, и цвета исчезают. Во-вторых, `accent` здесь — не
третий фирменный цвет, а тихий фон подсвеченной строки меню: так его понимает shadcn/ui, и так он чаще
всего используется. Фирменные цвета — `primary` (зелёный) и `secondary` (терракотовый).

Темы переключает next-themes: он ставит на `<html>` сразу и `class="dark"` (для `dark:` в Tailwind), и
`data-theme="dark"` (для daisyUI).

## Разработка

Проект разрабатывается локально и запускается на сервере. Инструментарий, закреплённый в Dockerfile,
— Node.js 26, поэтому проверки выполняются в контейнере того же мажорного релиза:

```bash
docker run --rm -v "$PWD":/app -w /app node:26-alpine sh -c 'npm install && npm test'
```

`npm test` запускает проверку типов (`tsc --noEmit`), линтинг (`biome check .`) и проверку каталогов
сообщений. Остальные скрипты:

```bash
npm run typecheck   # tsc --noEmit
npm run lint        # biome check .
npm run format      # biome check --write .
npm run test:i18n   # паритет ключей messages/*.json
npm audit           # известные уязвимости закреплённого дерева зависимостей
```

Biome заменяет ESLint и Prettier: одна зависимость вместо десятка, без графа peer-зависимостей, а
сортировка импортов и классов Tailwind работает из коробки (`useSortedClasses` в `biome.json`).

## Образы Docker

Каждая версия с тегом `vX.Y.Z` собирается и публикуется в GitHub Container Registry workflow-ом
`.github/workflows/docker.yml`: `ghcr.io/<владелец>/familee` получает теги `X.Y.Z`, `X.Y` и `latest`.
Пока репозиторий приватный, образ тоже приватный. Чтобы запускать опубликованный образ вместо сборки на
сервере, выполните `docker login ghcr.io` и укажите `image:` для сервиса `app` в `docker-compose.yml`;
по умолчанию сборка идёт из исходников.

## Версии

Familee следует [семантическому версионированию](https://semver.org) с номерами `MAJOR.MINOR.PATCH`.

- Пока мажорная версия равна `0`, минорный выпуск может менять поведение; `1.0.0` будет тогда, когда
  основные сценарии проверены в браузере на реальном архиве.
- Новая функция увеличивает минорный номер, исправление — номер патча. Изменение, которое требует ручной
  работы с данными или настройками, помечается в журнале изменений; после `1.0.0` оно увеличивает мажорный номер.
- Версия задаётся в `package.json` и отмечается в git аннотированным тегом `vMAJOR.MINOR.PATCH` на
  коммите выпуска.

## Резервные копии

Данные лежат в двух местах: схема `familee` в Postgres и том `familee_media` с оригиналами фотографий
и их превью.

```bash
docker exec -t postgres pg_dump -U <суперпользователь> --schema=familee --format=custom familee \
    > familee-$(date +%F).dump

docker run --rm -v familee_media:/data:ro -v "$PWD:/backup" alpine \
    tar czf /backup/familee-media-$(date +%F).tar.gz -C /data .
```
