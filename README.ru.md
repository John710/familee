# Familee — семейное дерево

*Читать на другом языке: [English](README.md)*

Приложение для ведения семейного архива: люди, союзы, события, места, источники и фотографии.
Дерево рисуется визуально — карточки с фотографией и ФИО, по нажатию карточка открывается на
редактирование. Интерфейс многоязычный, весь текст вынесен в `messages/*.json`.

Всё работает на вашем сервере в одном контейнере Docker и подключается к **уже запущенным**
Postgres, Redis и traefik — новые контейнеры для них не создаются.

## Что внутри

Next.js 16 (App Router, серверные действия) на React 19 и TypeScript 7. Данные — Postgres,
запросы через Drizzle ORM и драйвер postgres.js. Сессии — Redis (ioredis), вход — better-auth.
Оформление — Tailwind CSS 4 вместе с daisyUI 5 и компонентами shadcn/ui на radix-ui. Дерево
рисует @xyflow/react, раскладку считает d3-hierarchy. Превью фотографий делает sharp. Переводы —
next-intl. Проверка и форматирование кода — Biome.

Версии всех пакетов зафиксированы точно (без `^`) в `package.json`: обновление должно быть
осознанным действием, а не следствием пересборки образа.

## Требования на сервере

Docker с плагином compose. Уже работающие Postgres (с расширениями из состава contrib), Redis и
traefik. Приложение входит в их сети Docker, поэтому обращается к ним по именам контейнеров.

## Первый запуск

**1. База данных.** Подключитесь к своему Postgres суперпользователем и создайте роль и базу:

```sql
create role familee with login password 'придумайте_пароль';
create database familee owner familee;
```

Затем подключитесь к базе `familee` (всё ещё суперпользователем) и включите расширения — обычной
роли на это прав не хватит:

```sql
create extension if not exists pgcrypto;
create extension if not exists pg_trgm;
create extension if not exists btree_gin;
```

Отдельная база не обязательна: все объекты приложения живут в схеме `familee`, поэтому её можно
создать и внутри существующей базы. Тогда роли нужно право `create` на этой базе, а в
`DATABASE_URL` указывается имя существующей базы.

**2. Настройки.** Скопируйте `.env.example` в `.env` и заполните. Обязательно поменяйте
`DATABASE_URL`, `REDIS_URL`, `FAMILEE_HOST` и `BETTER_AUTH_SECRET` (`openssl rand -base64 48`).
Имена сетей `DATA_NETWORK` и `CACHE_NETWORK` можно посмотреть так:

```bash
docker inspect -f '{{range $n,$_ := .NetworkSettings.Networks}}{{$n}} {{end}}' postgres
docker inspect -f '{{range $n,$_ := .NetworkSettings.Networks}}{{$n}} {{end}}' redis
```

Если Postgres и Redis работают в одной сети, оставьте только `DATA_NETWORK` и удалите сеть
`cache` из `docker-compose.yml` — там об этом есть примечание.

**3. Сборка, схема, запуск.**

```bash
docker compose build
docker compose run --rm migrate     # накатывает db/migrations/*.sql
docker compose up -d
docker compose logs -f app
```

Сервис `migrate` — это разовый контейнер с одним лишь `psql`; ставить его на сервер не нужно.
Миграции идемпотентны, повторный запуск безопасен и применяется после каждого обновления кода.

**4. Демонстрационные данные (по желанию).** `db/seed.sql` создаёт вымышленную семью на четыре
поколения: повторный брак, пасынок, приблизительные и неполные даты. На ней удобно смотреть, как
выглядит дерево, пока своих данных ещё нет.

```bash
docker compose run --rm migrate seed
```

Скрипт каждый раз полностью удаляет дерево со слагом `demo` и создаёт его заново; настоящие
деревья он не трогает.

## Миграции

**Источник истины — рукописный SQL в `db/migrations/`.** Там не только таблицы, но и триггеры,
функции обхода дерева (`familee.ancestors`, `familee.descendants`, `familee.kinship`),
представления `familee.parent_child` и `familee.person_cards`, проверки нечётких дат и защита от
циклов в родстве. Drizzle используется только как типизированный конструктор запросов и зеркалит
этот SQL руками, файл за файлом.

Поэтому **`drizzle-kit generate` запускать нельзя**: он не видит рукописных функций и триггеров и
сгенерирует миграцию, которая их снесёт. Разрешены только безопасные команды:

```bash
npm run db:check     # сверить схему Drizzle с базой
npm run db:pull      # посмотреть, что реально в базе
npm run db:studio    # просмотр данных
npm run db:apply     # то же, что сервис migrate, если psql есть локально
```

Новое изменение схемы добавляется так: пишется файл `db/migrations/000N_*.sql` (идемпотентный,
со своей транзакцией и записью в `familee.schema_migrations`), затем правится соответствующий
модуль в `src/db/schema/`. Имена ограничений и индексов в SQL и в Drizzle должны совпадать —
на этом держится `db:check`.

## Языки

Чтобы добавить язык, нужно ровно два шага: положить `messages/<код>.json` (проще всего скопировать
`messages/en.json`) и добавить код в массив `locales` в `src/i18n/routing.ts`.

Переводить файл целиком не обязательно. Любой отсутствующий или пустой ключ автоматически берётся
из языка по умолчанию, так что интерфейс не сломается на полупереведённом файле — за это отвечает
`withFallback` в `src/i18n/request.ts`.

В базе данных нет ни одной надписи для человека. Значения перечислений, типы событий и степени
родства хранятся ключами (`male`, `birth`, `marriage`), а подписи к ним лежат в `enums.*` и
`events.*` в файлах переводов. Функция `familee.kinship()` возвращает два числа — сколько
поколений вверх и вниз, — а слово «двоюродная сестра» собирает уже приложение из `kinship.*`.
Благодаря этому новый язык не требует ни одной миграции.

Сам код проекта — комментарии, имена, документация — по-английски. По-русски только `messages/ru.json`
и этот файл.

## Оформление

Палитра объявлена один раз — как две темы daisyUI (`light` и `dark`) в `src/app/globals.css`.
Имена, которых ждут компоненты shadcn/ui (`bg-background`, `text-muted-foreground`,
`border-border`), объявлены там же в `@theme inline` и **ссылаются** на цвета daisyUI. Поэтому
обе библиотеки всегда согласованы, а править палитру нужно в одном месте.

Два нюанса, которые легко «починить» по ошибке. Во-первых, общие для обеих библиотек имена
(`primary`, `secondary`, `accent`, `info`, `success`, `warning`, `error`) в `@theme inline` не
переопределяются — иначе получится циклическая ссылка и цвета исчезнут. Во-вторых, `accent` здесь
не третий фирменный цвет, а спокойный фон подсветки строки в меню: так его понимает shadcn/ui, и
он используется чаще. Фирменные цвета — `primary` (зелёный) и `secondary` (терракотовый).

Тему переключает next-themes, выставляя на `<html>` сразу и `class="dark"` (для `dark:` у
Tailwind), и `data-theme="dark"` (для daisyUI).

## Разработка

Локально приложению нужны те же Postgres и Redis, поэтому проще всего пробросить их с сервера
через ssh и указать в `.env` адрес `127.0.0.1`:

```bash
ssh -N -L 5432:localhost:5432 -L 6379:localhost:6379 сервер
npm install
npm run dev
```

Проверки перед коммитом:

```bash
npm run typecheck   # tsc --noEmit
npm run lint        # biome check .
npm run format      # biome check --write .
```

Вместо ESLint и Prettier взят Biome: одна зависимость вместо десятка, нет графа peer-зависимостей,
который в связке ESLint 10 + typescript-eslint конфликтует на установке, и заодно сортировка
импортов и классов Tailwind (`useSortedClasses` в `biome.json`).

## Резервное копирование

Данные лежат в двух местах: схема `familee` в Postgres и том `familee_media` с оригиналами
фотографий и превью.

```bash
docker exec -t postgres pg_dump -U familee --schema=familee --format=custom familee \
    > familee-$(date +%F).dump

docker run --rm -v familee_media:/data:ro -v "$PWD:/backup" alpine \
    tar czf /backup/familee-media-$(date +%F).tar.gz -C /data .
```
