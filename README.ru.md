# Familee — семейное древо

*Читать на другом языке: [English](README.md)*

Familee — это место, где можно хранить семейный архив: людей, их браки и детей, события их жизни,
места, где они жили, документы, из которых мы о них знаем, и фотографии. Древо рисуется карточками
с фотографией и именем. Щелчок по карточке открывает её, и её можно сразу отредактировать.

Программа работает на вашем собственном сервере. Всё хранится в вашей базе данных и в вашем хранилище
фотографий, никуда ничего не отправляется. Familee использует контейнеры Postgres и Redis, которые уже
запущены на сервере, и своих не поднимает. Открыть архив можно по IP-адресу сервера и порту (это
вариант по умолчанию) или за Traefik по HTTPS на вашем домене.

Интерфейс по умолчанию английский, русский доступен по адресу `/ru`.

## Что умеет

- **Люди и семьи.** У каждого человека есть имена, пол, даты рождения и смерти, заметки, другие имена
  (девичья фамилия, фамилия по мужу, прозвище) и события жизни с местами. Даты могут быть такими же
  неточными, как источники: «около 1901», «между 1915 и 1918». Семья связывает партнёров и детей, а
  программа не даст человеку стать собственным предком.
- **Возможные дубли.** Архив ищет людей с одинаковым именем (без учёта регистра и диакритики) и
  одинаковыми годами рождения и смерти и показывает их на отдельной странице дерева. Сам он ничего не
  объединяет: вы оставляете верную запись, и имена, события, заметки, фотографии и союзы остальных
  переходят к ней.
- **Древо.** Карточки с фотографией и годами жизни, сверху вниз. Щелчок открывает панель с хронологией,
  заметками и альбомом. Режим фокуса показывает только предков и потомков одного человека. Если вы
  выбрали себя в древе, каждая карточка показывает, как этот человек связан с вами. Поиск переводит
  древо к нужному человеку. Живым показывается текущий возраст, умершим — тот, до которого они дожили.
- **Фотографии.** У каждого человека есть альбом с одной главной фотографией, которую можно обрезать
  до квадрата, как на карточке. У событий могут быть свои фотографии, а галерея показывает все фото
  дерева. У снимка есть подпись, альбом можно расставить в нужном порядке, и можно отметить, кто на
  фотографии, — имена показываются и в окне просмотра. Файлы можно перетащить прямо в альбом, и вся
  пачка загружается за один раз.
- **Библиотека.** Места, вложенные друг в друга (город в области, кладбище в городе). Источники — например,
  страница переписи или письмо — и цитаты, которые связывают человека или событие с источником.
  Истории и заметки. Поиск по всему этому сразу.
- **Дни рождения.** Ближайшие две недели по всем вашим деревьям: колокольчик в шапке, главная страница,
  страница дерева, страницы участников и людей.
- **GEDCOM.** Можно импортировать файл GEDCOM любой версии — программа сама узнаёт версию по заголовку
  файла. Перед записью вы видите предпросмотр и подтверждаете импорт. Человек из файла, у которого уже
  есть тёзка с теми же годами в дереве, присоединяется к его записи, а не добавляется второй раз, — в
  предпросмотре видно, кто именно. Дерево можно выгрузить в GEDCOM 7.0.
- **Календарь.** Дни рождения и дни свадеб дерева отдаются лентой iCalendar. Адрес есть на странице
  дерева (в нём ключ дерева, поэтому не передавайте его никому); календарь на телефоне подписывается на
  ленту наравне с остальным. В ленте только даты с полным днём: событие, известное до месяца, попало бы
  на день, которого никто не записывал.
- **Доступ.** В каждом дереве есть свои участники с ролями: владелец, администратор, соавтор и читатель.
  Участники приходят по ссылкам-приглашениям, а администратор может выдать сброс пароля. Владелец
  и администраторы видят историю изменений и устройства, с которых каждый вошёл в аккаунт. Владелец
  может удалить дерево, редактор — убрать человека в корзину.
- **Корзина.** Удаление человека убирает его в корзину дерева, а не уничтожает данные: имена, события,
  заметки, фотографии и союзы остаются, дерево просто перестаёт его показывать. Вернуть можно кого
  угодно и когда угодно. Владелец и администраторы могут удалить человека навсегда — только тогда
  исчезают файлы.

## Из чего сделано

Программа написана на TypeScript: Next.js 16 и React 19. Данные лежат в Postgres и читаются через
Drizzle ORM. Вход выполняет better-auth: сессии хранятся в Postgres и кешируются в Redis. Внешний вид
сделан на Tailwind CSS и daisyUI. Переводы — next-intl. Древо рисует @xyflow/react, а раскладку карточек
мы считаем сами. Превью фотографий делает sharp.

## Требования к серверу

- Docker с плагином compose.
- Уже запущенные на сервере Postgres и Redis. На сервере Postgres должны быть доступны расширения
  `pgcrypto`, `pg_trgm` и `btree_gin`.
- Контейнеры Postgres и Redis должны быть доступны по имени из одной Docker-сети — той, что указана в
  `DATA_NETWORK`. Familee подключается к этой сети и обращается к ним по имени.
- По желанию — Traefik, если нужен HTTPS на домене. Без него архив открывается по IP-адресу.
- По желанию — выход в `api.github.com`, чтобы футер мог сообщить о новой версии. Контейнер
  спрашивает о ней в фоне, не чаще раза в шесть часов; без выхода футер покажет только свою версию, и
  больше в архиве ничего не меняется.

## Первый запуск

**1. База данных.** Подключитесь к общему Postgres под суперпользователем и создайте роль и базу
для Familee:

```sql
create role familee with login password 'pick_a_password';
create database familee owner familee;
```

Затем подключитесь к базе `familee` (всё ещё под суперпользователем) и включите расширения. Обычная
роль этого делать не может:

```sql
create extension if not exists pgcrypto;
create extension if not exists pg_trgm;
create extension if not exists btree_gin;
```

Можно положить архив и в уже существующую базу. Все таблицы Familee лежат в собственной схеме
`familee`. В этом случае роли нужна привилегия `create` на эту базу, а `DATABASE_URL` указывает на
её имя.

**2. Настройка.** Скопируйте `.env.example` в `.env`, задайте файлу права `600` и заполните его.
Обязательно укажите `DATABASE_URL`, `REDIS_URL`, `DATA_NETWORK` и `BETTER_AUTH_SECRET`. Секрет
можно получить командой `openssl rand -base64 48`.

**3. Как открывать архив.** Выберите один из двух способов в `.env`:

- **По IP-адресу (по умолчанию).** Приложение открывается на сервере по порту `FAMILEE_PORT` (по
  умолчанию 3000), по обычному HTTP. Укажите `BETTER_AUTH_URL=http://<ip-сервера>:<FAMILEE_PORT>`,
  больше ничего не нужно. Для домашней сети этого достаточно. Если архив нужен из интернета, поставьте
  перед ним HTTPS-прокси.
- **За Traefik по HTTPS.** Укажите в `FAMILEE_HOST` свой домен, а в `BETTER_AUTH_URL` — `https://<домен>`.
  Затем включите в `.env` файл-надстройку Traefik:

  ```bash
  COMPOSE_FILE=docker-compose.build.yml:docker-compose.traefik.yml
  ```

  В `TRUSTED_PROXIES` укажите подсеть сети Traefik, например `192.168.90.0/24`. Тогда ограничение числа
  входов видит настоящий адрес каждого человека, а не адрес Traefik. В режиме «адрес и порт» оставьте
  поле пустым. Надстройка подключает приложение к сети прокси `TRAEFIK_NETWORK`, добавляет маршрут
  для вашего домена и убирает открытый порт, так что архив доступен только через Traefik. Точку входа и
  получение сертификата задают `TRAEFIK_ENTRYPOINT` и `TRAEFIK_CERTRESOLVER`.

`BETTER_AUTH_URL` должен совпадать с адресом, по которому вы открываете архив в браузере, включая схему и
порт. Если адреса не совпадут, вход будет отклонён как запрос с другого сайта.

**4. Сборка и запуск.**

```bash
docker compose build
docker compose up -d
docker compose logs -f app
```

Чтобы запускать опубликованный в реестре образ, а не собирать его на сервере, укажите в `.env` `COMPOSE_FILE=docker-compose.image.yml` и выполните `docker compose pull` вместо `docker compose build`. Файл закрепляет точный релиз в `FAMILEE_VERSION` — по умолчанию это тот релиз, с которым файл опубликован, никогда не `latest`, — так что обновление это смена числа и `up -d`. Оба compose-файла описывают одни и те же сервисы.

Контейнер сам приводит таблицы к версии образа перед запуском сервера, так что отдельного шага
миграций нет: обновление — это `pull` (или `build`) и `up -d`. Чтобы пропустить этот шаг, задайте
`SKIP_MIGRATIONS=1`. Сервис `tools` — временный контейнер, в котором есть только `psql`, так что
на сервере ничего устанавливать не нужно; он остаётся для демо-данных и smoke-тестов.

**5. Демо-данные (необязательно).** Демо показывает программу на вымышленной семье Каллахан из
Питтсбурга и Кливленда, на четыре поколения. В ней есть почти всё, что умеет Familee: иммиграция,
гибель на войне, два брака, аннулирование, гражданский союз, пасынок, приёмный сын, приблизительные
даты, места, источники, цитаты и заметки. Это хороший способ осмотреться, прежде чем вносить свою семью.

Создать демо можно двумя способами. Первый — командная строка:

```bash
docker compose --profile tools run --rm tools seed
```

Второй — кнопка на странице профиля администратора; перед созданием программа спрашивает подтверждение.
В обоих случаях дерево с адресом `demo` заменяется демо-семьёй вместе с её фотографиями и файлами.
Ваши деревья при этом не трогаются.

## Аккаунты и доступ

Открытая регистрация закрыта. Первый человек открывает один раз адрес `<BETTER_AUTH_URL>/setup` и
создаёт учётную запись администратора. После этого страница больше не открывается. Все остальные
получают ссылку-приглашение от владельца или администратора дерева. Ссылка действует 7 дней и
работает один раз.

Роли выдаются в каждом дереве: владелец, администратор, соавтор и читатель. Приглашение может дать
любую роль, кроме владельца. Владелец и администраторы меняют роли и удаляют участников на странице
участников. Администратор не может менять другого администратора или владельца, а менять свой доступ
не может никто. В профиле каждый видит устройства, с которых вошёл в аккаунт, и может завершить сеанс
на любом из них.

`BETTER_AUTH_URL` должен совпадать с адресом, который вы вводите в браузере, с портом, например
`http://192.168.0.10:3000` или `https://archive.example.com`. Иначе запросы входа будут отклонены.

## Часовой пояс

`APP_TIME_ZONE` — название часового пояса, например `Europe/Berlin`. По умолчанию это
`Asia/Vladivostok`. Пояс задаёт время в контейнере, так что все времена на экране показываются в нём.
По этому же дню считаются дни рождения в ближайшие две недели.

## Изменения базы данных

Структура базы описана обычным SQL в папке `db/migrations`. Каждый файл вносит одно изменение; файлы
применяются один раз и по порядку. Недостающие контейнер применяет сам при запуске, так что обновление —
это `pull` (или `build`) и `up -d`. Сервис `tools` тоже умеет применять их вручную, а ещё загружает
демо-данные (`seed`) и запускает smoke-тесты (`test`).

## Языки

По умолчанию интерфейс английский, русский доступен по адресу `/ru`. Чтобы добавить язык, создайте
один файл `messages/<код>.json`. Проще всего начать с копии `messages/en.json`: переведите значения и
задайте `locale.name` — название языка, написанное на самом этом языке. Языки определяются по именам
файлов при сборке образа, больше ничего менять не нужно.

Переводить весь файл сразу не обязательно. Ключ, которого нет или который пуст, берётся из английского,
так что частично переведённый язык работает.

## Резервные копии

Ваши данные лежат в двух местах: в схеме `familee` в Postgres и в томе `familee_media`, где хранятся
исходные фотографии и их превью. Копировать нужно оба — и проверять, что копия читается.

```bash
# 1. База. Без -t: псевдотерминал docker переводит концы строк, и pg_restore
#    больше не может прочитать бинарный архив.
docker exec postgres pg_dump -U <суперпользователь> --schema=familee --format=custom familee \
    > familee-$(date +%F).dump

# 2. Проверка: pg_restore перечисляет содержимое архива и падает, если дамп испорчен.
docker exec -i postgres pg_restore -l /dev/stdin < familee-$(date +%F).dump > /dev/null

# 3. Файлы. Снимайте сразу после дампа, чтобы обе копии описывали почти один момент.
docker run --rm -v familee_media:/data:ro -v "$PWD:/backup" alpine \
    tar czf /backup/familee-media-$(date +%F).tar.gz -C /data .
```

### Восстановление

Сначала остановите приложение, чтобы во время замены схемы никто не писал, затем восстановите базу
и верните файлы:

```bash
docker stop familee

docker exec -i postgres psql -U <суперпользователь> -d familee \
    -c 'drop schema if exists familee cascade'
docker exec -i postgres pg_restore -U <суперпользователь> -d familee --no-owner \
    < familee-YYYY-MM-DD.dump

docker run --rm -v familee_media:/data -v "$PWD:/backup" alpine \
    sh -c 'rm -rf /data/* && tar xzf /backup/familee-media-YYYY-MM-DD.tar.gz -C /data'

docker start familee
```

Один раз восстановите копию на отдельной базе заранее. Бэкап, который никто не восстанавливал, —
это надежда, а не бэкап.

## Мониторинг

Healthcheck контейнера спрашивает `/api/ready`: он отвечает 200, только когда отвечают и Postgres, и
Redis, а иначе называет, что не ответило. Поэтому `docker ps` показывает контейнер, у которого пропала
база, как `unhealthy`, а не как работающий. Тот же адрес годится для внешнего монитора (Uptime Kuma,
Gatus, `curl` из cron):

```bash
curl -fsS https://familee.example.com/api/ready
# {"status":"ready","checks":{"database":true,"redis":true},"time":"..."}
```

`/api/health` остаётся дешёвой проверкой живости — процесс отвечает, база не спрашивается — для
балансировщика, которому не нужен запрос к базе на каждый запрос.
